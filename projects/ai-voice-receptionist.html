An AI voice agent answers the clinic's phone, books and reschedules appointments through natural conversation, and writes every outcome straight into a Postgres database. n8n orchestrates the call-to-database logic; Supabase handles auth, real-time sync and row-level security; a React dashboard lets staff watch bookings appear live, call by call.

How it works

  1. Patient calls in — no account, no app, just the clinic's phone number.
  2. Vapi runs the conversation (speech-to-text → LLM → text-to-speech), following a structured system prompt tuned for this clinic: find out what the patient needs, list doctors, check real availability, confirm details out loud — all in natural Turkish, without exposing a function name or technical term to the caller.
  3. n8n executes the actions. Every capability the assistant has — get_doctors, get_available_slots, check_patient, book_appointment, cancel_appointment — is a custom tool backed by its own webhook-triggered n8n workflow, where the business logic lives: re-checking a slot is still open before committing, matching a caller to an existing patient by phone or creating one on the spot, writing the booking, logging the call.
  4. Supabase is the source of truth — Postgres tables for patients, doctors, schedules, appointments, call logs, and a reminder queue, with row-level security scoping every read/write by role.
  5. The dashboard updates itself via Supabase Realtime — the moment a call ends, the new row appears on the admin's screen, no refresh needed.
  6. Reminders close the loop: a scheduled workflow has Vapi place outbound calls ahead of upcoming appointments.

Tech stack

  • Voice AI — Vapi (LLM-driven conversational agent, function calling, Turkish-language prompt engineering)
  • Automation — n8n (self-hosted on Docker), webhook-triggered workflows, exposed for development via ngrok
  • Backend — Supabase: Postgres, Auth, Row-Level Security, Realtime
  • Frontend — React 18, TypeScript, Vite, Tailwind CSS, React Router — three role-scoped portals (admin, doctor, patient), bilingual UI (TR/EN)
  • Deployment — static frontend build, versioned SQL migrations for schema + seed data

What it demonstrates

  • Designing a voice-first UX where an LLM makes real decisions (availability, identity, conflicts), not just chats
  • Wiring a no-code automation layer to a relational schema without losing data integrity — race conditions and duplicate patients handled explicitly
  • Row-level security modeled around real-world roles, not a single admin flag
  • A frontend treating the database as one source of truth for two clients at once: a human on the web and an AI on the phone
  • Full ownership of the stack end to end — voice, automation, database, UI
